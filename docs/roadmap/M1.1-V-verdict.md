## Finding

The source fix is locally credible for the observed disposal-order defect.

- `SpriteAtlasCache.loadPack()` stages replacement entries and keeps the active map live while images load (`apps/game-web/src/sandbox/animation/spriteAtlas.ts:70-107`).
- `UnitRenderSystem` retires its batches in `onBeforeCommit`, before the atlas commits and disposes old textures (`apps/game-web/src/sandbox/UnitRenderSystem.ts:149-162`, `216-224`).
- Generation cancellation disposes a late texture and does not touch the active map (`spriteAtlas.ts:182-188`, `275-288`).
- Missing art remains an explicit `missing` status with a visible placeholder. The after-run captures reported all four unit and three building assets as `ready`.

The source paths in `6e4d580` and the current review HEAD are identical for the three reviewed paths. The focused test source checks the retirement hook order, but it does not cover cancellation, late completion, image failure, or re-entrant replacement.

## Remaining lifecycle risk

There is a latent cleanup gap in `SpriteAtlasCache.loadPack()`: if `onBeforeCommit()` re-enters `loadPack()` or otherwise changes generation, the second guard returns without disposing the old `pendingLoad.entries` because the pending-load identity no longer matches. The current `UnitRenderSystem` callback only clears batches, so this re-entrant path was not demonstrated as a current production path. It remains unverified and is owned by `spriteAtlas.ts`.
