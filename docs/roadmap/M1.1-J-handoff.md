## Root cause

The previous configuration selected the fixed directory `/tmp/pastel-foundry-e2e` and ran `mkdir -p` before starting the content server. It did not copy `content/dev-pack-v2`. The default content server could therefore start with an empty or stale pack. A later invocation could reuse mutations from an earlier invocation.

## Implemented behavior

`playwright.config.ts` now applies this selection order:

1. `PLAYWRIGHT_CONTENT_PACK_DIR`, when supplied, is used exactly.
2. `CONTENT_PACK_DIR`, when supplied, is used exactly.
3. Otherwise, when the content server is enabled, the config creates a unique directory with `mkdtempSync` and copies the contents of the checked-in `content/dev-pack-v2` into it with `cpSync`.
4. The selected directory is propagated through `CONTENT_PACK_DIR` and the content web-server environment.

The generated directory name uses the `pastel-foundry-e2e-` prefix under the host temporary directory. The content web-server command no longer creates a directory. This prevents an explicit missing or empty user path from being silently created or merged with the fixture.

The config sets the internal `PLAYWRIGHT_GENERATED_CONTENT_PACK_DIR` marker after the first generated copy. Playwright worker config deserialization inherits that environment. A parent and worker evaluation therefore select the same generated directory and do not copy again. The normal `CONTENT_PACK_DIR` propagation remains available to tests and to the content server.

When `PLAYWRIGHT_SKIP_CONTENT_SERVER=1` is set, no generated fixture copy is made and the content web-server entry is omitted. The offline game path does not require the content server or a content-pack selection.

Because the content pack is mutable during Foundry acceptance, the config defaults to one worker whenever the content server is enabled. This serializes the default projects against the one mutable pack. The offline path keeps the existing non-content-server worker behavior. Assertions were not changed.
