# M1.1-M handoff — CI mode routing correction

Status: IMPLEMENTED AND LOCALLY VERIFIED. Scope is M1.1 only. This change does not claim a whole-milestone, native-device, or human-design pass.

Repository: `/home/bobbyranka/Projects/pastel-rts-m11-ci-mode`
Branch: `m1.1/ci-mode`

## Root cause

`playwright.config.ts` defaults `PLAYWRIGHT_SERVER_MODE` to `preview`. The previous CI browser step set only `CI=true`, so the complete authoring suite ran against preview servers. That sent the Foundry runtime to the baked game origin, changed the development framing, and skipped tests guarded for the development studio. The production offline test also had no separate CI route.

## Implemented routing

Changed only `.github/workflows/ci.yml` and this handoff.

- The existing full `Visual and interaction tests` gate is now named `Visual and interaction tests (developer studio)` and sets `PLAYWRIGHT_SERVER_MODE=dev`.
- A separate `Production preview offline verification` gate runs the existing `apps/game-web/e2e/m11c-baseline.spec.ts` production test with `--project=chromium`, `PLAYWRIGHT_SERVER_MODE=preview`, and `PLAYWRIGHT_SKIP_CONTENT_SERVER=1`.
- The production build remains before both browser gates. The dev route runs against the developer studio, and the preview route exercises the actual build output without a content server.
- No test, snapshot, threshold, Playwright configuration, product source, fixture, or security control changed.

## Preserved gates

The existing typecheck, lint, unit-test, production-build, Playwright browser cache/install, Playwright failure-report upload, iOS web bundle build/sync, Xcode project generation, and iOS simulator compile steps remain present and blocking. No failure is hidden. No functional test is skipped by workflow logic. No snapshot or threshold is changed. No new infrastructure, credential, permission, or billing change was made.
