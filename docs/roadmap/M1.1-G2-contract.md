M1.1-G2 contract

Goal

Strengthen the M1.1-G browser acceptance so the exported runtime bug bundle comes from a real player move, not an idle scenario.

Scope

- Update apps/game-web/e2e/m11g-bundle.spec.ts only.
- Add fresh evidence under the unique M11G_ARTIFACT_DIR.
- Add a concise handoff under docs/roadmap/M1.1-G2-handoff.md.

Acceptance

1. Load the actual interaction lab with isolated content and normal configured Playwright launch.
2. Select a friendly unit through a pointer click at its projected canvas position.
3. Send a move through a second pointer click on the canvas.
4. Observe a real move command, an accepted command result for that command, and a measurable unit position change.
5. Export through the visible Export bug bundle control.
6. Require the exported replay to contain the exact non-empty ordered command stream and the matching accepted result.
7. Require a nontrivial checksum sequence with more than one recorded checksum and more than one hash value.
8. Import in a new browser context and compare the complete expected and actual checksum sequences entry by entry.
9. Keep the historical-revision rejection case and prove active-state preservation.
10. Record commands, accepted results, movement, checksums, fresh replay, rejection, browser errors, and screenshots as evidence.

Non-goals

- No new simulation or navigation behavior.
- No fake command logs, injected commands, fabricated checksums, blocker setup, or direct command-client calls in the G2 acceptance.
- No changes to runtime, HUD, content client, configuration, schemas, packages, PROGRESS.md, or numbered uploads.
- No unsafe Chromium flags, deployment, push, or device claim.

Invariants

- The existing six bug-bundle unit tests remain unchanged.
- The refusal path must not mutate the active scenario, revision, content hash, seed, command count, or expected checksums.
- Fresh replay uses the imported bundle through the existing visible import path.
- The artifact directory is unique for this run and is disposable.
