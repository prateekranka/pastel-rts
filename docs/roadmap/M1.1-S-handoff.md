# M1.1-S handoff — texture lifetime

Status: narrow lifecycle fix complete and verified from existing real runtime evidence. This is not an overall gate, device pass, or 20-minute soak claim.

## Proven cause

`SpriteAtlasCache.loadPack()` cleared and disposed active atlas entries before the asynchronous replacement completed. `UnitRenderSystem` cleared its batches only after all image loads completed. During that window, `ensureLoaded()` replaced a placeholder and disposed it while a live unit material still referenced the same texture. Three.js could then re-upload that disposed texture without a later owner.

The pre-fix focused run proves the identity violation. `docs/roadmap/M1.1-S-focus-before-fix-artifacts/replacement-01.json` records four unit texture disposals with non-empty `liveRefs`. The longer raw Q run records the symptom: renderer textures 7 -> 12 over 12 cosmetic replacements while geometries stayed at 17.

## Fix

`SpriteAtlasCache` now loads each replacement into a staged entry map. The active map remains valid while the load is pending. The caller supplies an `onBeforeCommit` hook. `UnitRenderSystem` retires its batches in that hook. Only after that hook returns does the cache swap the staged map and dispose old textures. Per-generation cancellation still disposes stale staged textures and does not touch active textures.
