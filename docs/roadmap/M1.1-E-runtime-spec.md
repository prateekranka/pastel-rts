## Goal

Connect the interaction lab to one immutable published Foundry revision in explicit studio mode. Keep the packaged fixture path offline and deterministic. Make content replacement, save/load, replay, comparison, and QA artifacts truthful and reproducible.

## Non-goals

Do not change packages/simulation or packages/navigation. Do not change the content server, content schema, Foundry, editor projection, native bridge, fixture pack, root package files, lockfile, existing benchmark camera math, combat, economy, fusion, folding, or later roadmap work.

## Runtime modes

- `content=bundle` or an omitted `content` query uses the relative `content/dev-pack-v2/pack.json` fixture and relative scenario/map/assets. It does not open EventSource and does not request `/dev-content`.
- `content=studio` is the only development path for publication APIs. It reads `/dev-content/v2/publication`, then the selected revision metadata and `/dev-content/v2/revisions/:revision/pack`. Its asset base is `/dev-content/v2/revisions/:revision/assets/`.
- `revision=<safe revision>` pins a historical revision. Without it, studio mode follows the current published revision after a reconnect or publication event. The installed revision never changes without metadata and pack validation.

## Publication client contract

The client consumes these exact APIs. It does not emulate them:

- `GET /v2/publication` -> `{ currentRevision, draftRevision, current }`.
- `GET /v2/revisions/:revision` -> validated `RevisionMetadata`.
- `GET /v2/revisions/:revision/pack` -> validated `PackV2`.
- `GET /v2/revisions/:revision/assets/<logical path>` -> allowlisted immutable runtime or data asset.
- `GET /v2/draft/pack` and `GET /v2/draft/assets/<logical path>` are not runtime sources.
- `POST /v2/acknowledgements` with `{runtimeId, scenarioId, revision, simulationRulesHash, restartRequired}` after a pack and scenario are installed.
- `GET /v2/acknowledgements` is optional status readback for UI; no acknowledgement is treated as authoritative simulation state.

A response is accepted only after HTTP status, JSON shape, PackV2 validation, revision equality, pack id equality, and content hash identity pass. Metadata asset paths are logical paths only. The client constructs URLs from the fixed endpoint and never accepts a local disk path.

## Replacement state machine

`idle -> loading -> installed | failed`. A failed replacement keeps the last installed pack, asset base, scenario, and rendered art. The UI shows the failure and the requested revision.

A publication event or reconnect performs a bounded metadata resync. Duplicate events and out-of-order responses are ignored by request generation and revision identity. EventSource retries with bounded backoff and closes on dispose. It never starts outside `content=studio` and never starts in a packaged build.

- If the new metadata has the same `simulationRulesHash`, replacement is cosmetic. Keep the worker and authoritative state. Update the renderer pack and asset base. Async texture loads are generation guarded. The prior texture remains in use until the replacement texture succeeds.
- If the rules hash differs, do not mutate the worker or current match. Show `restart required` with an explicit restart/retest action. A user action may initialize the selected revision and scenario from tick zero. The current match remains usable until that action.
- A selected historical revision stays pinned. A current-publication event reports a pending newer revision instead of silently switching the pinned match.

## Scenario identity and replay

A save document contains schema version, pack id, exact revision, manifest/content hash, visual hash, simulation-rules hash, map id and complete validated map data, scenario id and complete validated scenario data, seed, replay tick, command envelopes, command results, and checksums. It contains no executable code or path outside the selected immutable content.

Import validates every identity and coordinate. It rejects unknown or mismatched revision, pack, rules hash, map, scenario, malformed command, checksum, or replay tick. It never substitutes the current map, current pack, or a bundled fixture. Reset clears commands and checksums and restarts the current scenario with the same selected revision and seed.

A/B comparison accepts two immutable revision inputs and one shared scenario/map/seed/command log. Each side runs the existing `runSimulationReplay` API independently. The result records both revisions, content hashes, rules hashes, checksum sequences, and equality flags. Different rules are a valid different-result outcome, not a failed equality assertion.

## Render and disposal invariants

- Snapshot row identity is `{index,generation}`. Registry mappings survive dense row changes and delete stale mappings when a generation is no longer live.
- A blocker/building accepted by the worker is visible in pickable readback after the command result and snapshot. A building id is not treated as a unit id.
- Reference images never enter runtime archetypes or animation clips.
- Missing art is an explicit diagnostic state. It is not silently presented as final authored art.
- Replacing or disposing a render system invalidates all in-flight loads. Late textures are disposed. Replaced textures, materials, and geometries are disposed exactly once.
- Native pause/resume uses the worker pause state. Resume does not advance missed ticks. The render resume frame is excluded from frame samples.
- Zoom changes camera presentation only. It does not remove command controls.

## Bounded diagnostics

Expose frame distribution, simulation and navigation timings, draw calls, texture and geometry counts, renderer backend/context, active revision, rules hash, scenario, seed, and replacement status. Keep existing benchmark diagnostics. CPU submission metrics are labelled as CPU metrics. Desktop/Linux evidence is not physical iPad proof.

## CLI contracts

`qa:scenario` and `qa:bundle` are implemented in the two owned script files. They require explicit input paths and output paths, validate all JSON and hashes, reject traversal, corrupt or unknown data, use no remote fetch, and return nonzero for invalid input. Repeated runs over the same inputs produce byte-identical normalized output. Bundle output is an allowlisted artifact containing scenario/map/seed/commands, content revision and hashes, checksum evidence, bounded diagnostics, and reproduction steps. It excludes credentials, private local paths, arbitrary files, and executable content.
