## Delivered backend behavior

Existing v1 and v2 authoring, `/pack`, `/pack?schema=2`, publish, and revert APIs remain available.

Wave 2 routes:

- `GET /v2/revisions/:revision/pack`
  - Returns the validated immutable PackV2 for the selected revision.
- `GET /v2/revisions/:revision/assets/<logical-path>`
  - Serves only assets allowlisted by that revision metadata. Map and scenario JSON are included.
  - Unknown assets return 404. Encoded traversal returns 400.
  - Missing or changed published assets make the integrity failure visible.
- `GET /v2/draft/pack`
  - Returns the validated mutable draft PackV2.
- `GET /v2/draft/assets/<logical-path>`
  - Serves only paths referenced by the draft PackV2.
- `GET /v2/references/:id/image`
  - Serves only a registered reference attachment. Reference bytes remain below `.content-publication/references/` and are never copied into a runtime revision.
- `POST /v2/acknowledgements`
  - Requires bounded `runtimeId`, `scenarioId`, a safe existing revision, the matching `simulationRulesHash`, and boolean `restartRequired`.
  - Stores at most 32 entries in volatile process memory. It does not write PackV2, publication state, simulation state, or gameplay truth.
- `GET /v2/acknowledgements`
  - Returns the bounded volatile acknowledgement list.
- `POST /v2/validate`
  - Requires `expectedDraftRevision`.
  - Validates the draft and referenced assets without publishing.
  - Checks the draft cursor separately from the published cursor.

Publication and asset safeguards:

- `GET /v2/publication`, `/health`, `/pack`, and `/pack?schema=2` validate the current migrated revision, manifest hash, metadata allowlist, asset hashes, dimensions, data files, and legacy manifest before returning it.
- Every uploaded PNG is decoded before storage. Uploads have an 8 MiB PNG limit, 4096-pixel dimension limit, 16,777,216-pixel area limit, decoded scanline limit, and RGBA output limit. Zlib output is bounded before allocation of decoded scanlines.
- Each upload is written to `.content-publication/originals/<sha256>.png` before a mutable draft asset path is replaced. Originals are write-once and survive multiple unpublished replacements, failed publication, revert, and removal.
- Revision snapshots assemble in a temporary directory and advance the publication cursor only after validation and atomic rename. Failed state rename removes only the new owned revision and leaves the prior state readable.
- Mutable pack directories, reference directories, original storage, published assets, draft assets, and selected pack roots reject symbolic links. Relative paths reject absolute, dot, dot-dot, backslash, NUL, colon, malformed, and repeatedly encoded traversal forms.
- Request bodies are bounded while received at 16 MiB. Declared oversized bodies return 413 without buffering the body.
