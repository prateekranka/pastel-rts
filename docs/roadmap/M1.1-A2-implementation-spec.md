# M1.1-A2 implementation contract

## Goal

Complete the wave 2 backend and studio integration boundary on top of aab0981. Preserve all existing v1/v2 authoring and publication APIs. Make published, draft, historical, reference, acknowledgement, validation, and studio lifecycle behavior observable and safe.

## In scope

- `packages/content-schema/**` only when a shared validation/type helper is required.
- `tools/content-server/**` for wave 2 routes, immutable draft-original storage, publication validation/transaction guards, HTTP limits, and focused tests.
- `scripts/dev-studio.mjs` and `scripts/studio-foundry.vite.mjs` for explicit custom-port origins, studio-mode game links, cancellation, and child process-group shutdown.
- Root `package.json` script names `qa:scenario` and `qa:bundle`, pointing to E-owned implementations.
- `docs/roadmap/M1.1-A2-handoff.md` and this contract.

## Out of scope

No runtime source, Foundry source, fixture content, QA test configuration, native files, simulation/navigation packages, new QA script implementation, model/profile/security changes, or later milestone work.

## Backend invariants

- `PackStore` is the authoritative owner of draft/publication files. Acknowledgements are in-memory status only. They never affect PackV2, publication state, simulation state, or gameplay truth.
- A draft cursor and published cursor are checked independently. Draft mutations and `/v2/validate` compare `expectedDraftRevision` to `state.draftRevision`; publish/revert compare their publication precondition to `state.currentRevision`.
- Every uploaded PNG is decoded and validated before storage. HTTP bodies are bounded while received. PNG dimensions, decoded scanline bytes, and RGBA output bytes are bounded before allocation.
- Before any mutable draft PNG path is replaced, its bytes are stored once at a content-addressed path below `.content-publication/originals/`. Original files are write-once and survive failed publication, revert, and draft removal.
- Reference attachments remain below `.content-publication/references/`. They are never collected into revision runtime/data assets. Reference image serving requires registered metadata and the requested id.
- Historical and draft asset routes use metadata/reference allowlists. No route resolves an arbitrary path from the URL. Missing or unknown assets return visible 404/errors.
- Publication builds a temporary revision, validates manifests and all referenced assets, renames only after success, and advances state only after the readable snapshot exists. Failure removes only its temporary revision and leaves the last current revision and cursors unchanged.
- GET publication validates the migrated current revision and its allowlisted manifest/assets. Corrupt or missing current content is an error, not a successful status response.

## Wave 2 routes

- `GET /v2/revisions/:revision/pack` returns the validated immutable PackV2 for that revision.
- `GET /v2/revisions/:revision/assets/<logical path>` serves only that revision metadata's asset allowlist, including map/scenario JSON.
- `GET /v2/draft/pack` returns the validated draft PackV2.
- `GET /v2/draft/assets/<logical path>` serves only paths referenced by the draft PackV2.
- `GET /v2/references/:id/image` serves only the registered attachment for `id`.
- `POST /v2/acknowledgements` accepts bounded `{runtimeId,scenarioId,revision,simulationRulesHash,restartRequired}` after revision/hash validation. `GET /v2/acknowledgements` returns at most 32 volatile entries.
- `POST /v2/validate` accepts `{expectedDraftRevision}`, validates the current draft and referenced files without publication, and returns `{ok:true,draftRevision}`.

## Studio invariants

- Game receives `VITE_CONTENT_SERVER_URL` for the selected content origin.
- Foundry receives `VITE_GAME_WEB_ORIGIN`, `VITE_CONTENT_SERVER_URL`, and `VITE_CONTENT_STATUS_URL` for the actual custom ports.
- Printed game links include `?mode=interaction-lab&content=studio`.
- A cancelled readiness wait rejects promptly and always settles owned process groups. An unrelated listener remains untouched on port collision. SIGTERM works before readiness and during steady state.
- The temporary content option is explicitly named and resolves a caller-selected directory. It never deletes caller data.
