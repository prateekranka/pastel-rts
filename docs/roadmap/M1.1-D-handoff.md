Delivered

- Shared library search by stable ID, display name, faction, kind, and tags.
- Kind filter and disabled-content filter.
- Unit and building edit routes with new-content and clone query support.
- Same-stable-ID replacement through draft `PUT` mutations.
- Unit/building duplicate, enable/disable, and remove controls.
- Dependency-aware remove handling. A dependency conflict is shown before the force-removal warning. The editor does not claim that force removal is publishable.
- Reference attachment browsing, upload, image route, and removal. The UI labels references as review-only. Reference images are not runtime content in the client contract.
- Dirty-state confirmation for Foundry navigation and `beforeunload`.
- Bounded undo/redo snapshots for fields, selected frame, building blocked-cell mask, and pending replacement image data.
- Generation guards for asynchronous image loads and replacement previews.
- Object URL cleanup in the existing file-image loader.
- Clone-from image adoption as a pending PNG so a new stable ID does not lose its source during save.
- Draft API calls include an explicit `expectedDraftRevision`.
- HTTP 409 revision-conflict messages retain local values and explain deliberate refresh/reconcile. Local editor state is not discarded.
- Explicit workflow strip: `Draft -> Validate -> Preview -> Publish revision -> Revert`.
- Validation is enabled only for an explicitly saved draft and calls `/v2/validate` with `expectedDraftRevision`.
- Publish uses the current publication cursor and does not run from a dirty editor.
- Revert selects a retained revision, confirms the effect, and reports the new publication ID while retaining originals.
- Status strip shows Game, Foundry, and Content links, connection state, current/draft revisions, rules restart state, and runtime/scenario acknowledgement state.
- Acknowledgement polling is bounded, abortable, and cleaned up on `pagehide`. A missing endpoint is displayed as unavailable. It is not shown as acknowledged.
- Sandbox links include `mode=interaction-lab`, `content=studio`, `spawnUnit` or `spawnBuilding`, `seed`, `scenario`, and the current publication `revision`.
- Shared `apps/game-web/src/camera/previewProjection.ts` uses `IsometricCamera`, `CELL_SIZE`, named zoom stops, isometric constants, and map size. The Foundry preview draws gameplay-default and explicit 70-percent projections, ground anchors, selection/collision footprints, direction status, and frame-grid overlays.
- Proxy and missing-direction states are labeled. The preview does not fabricate facing frames.
- Sheet inference now selects the known 128x256 fixture as a 4x8 grid of 32x32 frames. Explicit inferred source and frame dimensions flow into the manifest after all controls are written. The update is followed by a queued refresh so programmatic control changes cannot leave a stale manifest.
- Responsive dark Foundry layout keeps controls at practical touch sizes and permits normal document scrolling.

Non-coder walkthrough after A2 is available

1. Start the isolated content, Foundry, and game services. Open `http://127.0.0.1:17374/#/library`.
2. Search by stable ID or name. Use Type and Show disabled to narrow the shared library.
3. Use Edit on a unit or building. Keep the Stable ID unchanged to replace source art. Use Duplicate for a new ID. Use Enable/Disable for draft state. Use Remove and read the dependency warning before any force action.
4. In the editor, choose a PNG. Confirm source dimensions. For a unit, confirm frame width/height, clip FPS, directions, anchor, world height, selection radius, and collision radius. Use the frame-grid, footprint, and direction toggles. Proxy and missing frames remain labeled.
5. Click Save draft. This changes the draft cursor only. The stable ID remains visible. The retained publication source is not overwritten.
6. Click Validate saved draft. This calls `/v2/validate` only after the explicit draft save.
7. Click Preview draft to review the current editor state. This does not publish.
8. Click Publish revision. The status strip reports the new publication revision and waits for runtime acknowledgement. A rules hash change requires an explicit runtime restart/retest.
9. Click Test in Sandbox. Confirm the URL contains `mode=interaction-lab`, `content=studio`, the selected stable ID, seed, scenario, and actual publication revision.
10. Choose a retained revision, click Revert selected, and confirm. Foundry reports the new publication ID. The original retained revision remains available.
11. Reload the editor. The saved draft and retained sources remain identified by stable ID. Reference attachments remain in the separate Reference attachments panel and never appear as runtime art.
12. To test conflict handling, make a separate draft mutation, then save with the old cursor. Foundry must show HTTP 409 conflict guidance and keep the local fields/image for deliberate refresh and reconciliation.
